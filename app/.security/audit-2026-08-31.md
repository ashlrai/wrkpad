## Executive Summary

Ashlr Agent Board has a strong local-first baseline: Electron sandboxing and
context isolation are enabled, Node integration is disabled, actions are
allowlisted, consequential actions require short-lived confirmation bound to a
specific renderer and workspace, command arguments avoid shell interpolation,
and status payloads are bounded and normalized. Automated source, dependency,
and secret scans found no alerts.

Manual review initially found a high-severity renderer trust-boundary issue and
a low-severity executable-resolution issue. Both were remediated and regression
tested in the worktree during this audit. The local package was rebuilt after
the fixes and its renderer policy, privacy declarations, and packaged-source
inventory were inspected. It remains ad-hoc signed and is not suitable for
trusted public distribution.

**Residual Risk Rating:** Medium
**Open Findings:** 0 Critical, 0 High, 1 Medium, 0 Low
**Resolved During Audit:** 1 High, 3 Low

### MEDIUM

#### AAB-002: macOS artifact is not signed or notarized for public distribution

**Location:** `package.json` build configuration; local artifact
`release/mac-arm64/Ashlr Agent Board.app`

**Description:** `codesign -dv --verbose=4` reports an ad-hoc, linker-generated
signature, no Team Identifier, unsealed resources, and an unbound `Info.plist`.
Gatekeeper assessment fails. The new package workflow explicitly produces a
short-lived unsigned preview; no workflow provides Developer ID signing,
hardened runtime, notarization, or checksum/provenance publication.

**Impact:** Users cannot reliably distinguish an official build from a modified
one, and macOS will warn or block normal installation. Encouraging users to
bypass Gatekeeper would weaken the project's supply-chain posture.

**Remediation:** Keep local directory builds clearly labeled as development
artifacts. Before publishing binaries, use a protected GitHub Environment for
Apple credentials, sign with Developer ID Application, enable hardened runtime,
notarize and staple, publish SHA-256 checksums, and verify the downloaded
artifact in CI. Do not expose signing credentials to pull-request workflows.

### LOW

None open after remediation of AAB-003, AAB-004, and AAB-005; see Resolved
During Audit.

## Resolved During Audit

### AAB-005: Packaged macOS metadata advertised unused broad capabilities

**Location:** generated `Ashlr Agent Board.app/Contents/Info.plist`; package build
configuration in `package.json`

**Description:** The initial rebuilt bundle set `NSAllowsArbitraryLoads=true`
and included generic camera, microphone/audio-capture, and Bluetooth usage
descriptions. The current app does not implement remote networking or media
capture, and its Electron permission handler denies every renderer permission
request.

**Impact:** These declarations are broader than the product's audited behavior,
create misleading privacy expectations, and could expand the effect of future
native or dependency behavior. They do not currently grant those permissions by
themselves, which limits severity.

**Resolution:** A fixed `afterPack` hook now replaces App Transport Security with
`NSAllowsArbitraryLoads=false` and removes the unused camera, microphone/audio,
and Bluetooth descriptions before signing. The rebuilt package was inspected
with `plutil`; only the restrictive ATS dictionary remains.

**Status:** Resolved for package metadata. AAB-002 still blocks public binary
distribution.

### AAB-001: Trusted renderer and IPC boundary

**Original severity:** High

**Resolution:** Packaged mode now ignores `VITE_DEV_SERVER_URL`. Development
accepts only the exact `http://127.0.0.1:5173` origin. The window denies new
windows, webviews, permission requests, and navigation away from its selected
renderer. Every IPC handler is wrapped by a shared guard that requires the
current main window, its main frame, and the exact trusted URL.

**Evidence:** `electron/main.cjs:33-62`, `electron/renderer-trust.cjs:1-28`, and
three negative/positive trust tests in `electron/renderer-trust.test.cjs`.

**Status:** Resolved in source and present in the rebuilt local package.

### AAB-003: Deterministic executable resolution

**Original severity:** Low

**Resolution:** Command actions now resolve tool names to executable absolute
paths from explicit user-local, Homebrew, and system directories. The inherited
`PATH` is not consumed in production; `envPath` exists only as an explicit test
seam. Electron's OS-backed `app.getPath('home')` is passed from the main process
through mission collection and every action execution; the production action
registry no longer reads environment-controlled `HOME`. Names that could escape
a search root are rejected.

**Evidence:** `electron/tool-resolver.cjs:1-35`, `electron/main.cjs:98-125`,
`electron/action-registry.cjs:63-93`, integration in
`electron/mission-control.cjs`, and four resolver tests.

**Status:** Resolved.

### AAB-004: Production renderer policy retained development allowances

**Original severity:** Low

**Resolution:** Vite now emits separate development and production connection
policies. Development permits only the exact loopback Vite HTTP/WebSocket
endpoint; the packaged renderer emits `connect-src 'none'`. Navigation, new
windows, webviews, and permissions remain denied by the main process.

**Evidence:** `index.html`, `vite.config.ts`, and direct inspection of the rebuilt
`dist-renderer/index.html` and packaged `app.asar`.

**Status:** Resolved.

### INFORMATIONAL

- `contextIsolation: true`, `nodeIntegration: false`, and `sandbox: true` are
  explicitly configured.
- The preload exposes narrow functions rather than raw `ipcRenderer`.
- The main process binds every IPC call to the selected trusted main-frame URL
  and rejects cross-frame, cross-window, or cross-origin calls.
- New windows, webviews, renderer permission requests, and cross-origin
  navigation fail closed.
- No `eval`, `new Function`, `dangerouslySetInnerHTML`, cookie, webview, iframe,
  remote API, or renderer-side secret storage was found.
- The CSP rejects inline scripts; the inline-style allowance is required by the
  current styling approach and does not independently permit script execution.
- React escapes local tool output before it is displayed.
- Child processes use `spawn()` with argument arrays. Terminal command strings
  shell-quote the user-selected workspace and then escape AppleScript string
  delimiters.
- Action IDs are allowlisted. Confirmation tokens are random, expire after 30
  seconds, are single-use, and are bound to action, renderer, workspace, and
  hold duration where applicable.
- Flight Check disables mapped actions and clears pending approvals.
- Receipt input is size- and shape-bounded; the saved evidence is reconstructed
  from main-process events, written via exclusive temporary creation with mode
  `0600`, and atomically renamed.
- Agent/Fleet command output is byte-bounded, schema-checked, stripped of control
  characters for display fields, and reduced before reaching the renderer.
- No authentication, HTTP server, database, cookies, webhooks, or CORS surface
  exists in this desktop-only repository.

## Recommendations (Prioritized)

### Immediate (before public binary release)

1. Keep downloadable binaries private until AAB-002 signing and notarization are
   implemented and independently verified.
2. Enable GitHub private vulnerability reporting, CodeQL, Dependabot, dependency
   review, secret scanning, and branch protection on the public repository.

### Short-term (1-2 weeks)

1. Add release provenance/checksum verification and an Electron security
   regression checklist.
2. Review and refresh the workflow's immutable GitHub Action SHAs through
   Dependabot rather than reverting to mutable tags.

### Medium-term (1-3 months)

1. Evaluate Electron fuses for packaged releases, including disabling
   `RunAsNode`, `NODE_OPTIONS`, and unneeded CLI inspection capabilities.
2. Establish scheduled binary/dependency review for native build tooling.
3. Add a documented threat model covering local malicious repositories,
   compromised hooks/status producers, and hardware takeover transitions.

## Release conclusion

**Source publication:** acceptable with this report and policy visible.

**Downloadable macOS binary:** not approved by this audit until it is rebuilt
from the repaired source and AAB-002 signing/notarization is implemented. A
green source scan does not prove binary distribution integrity or physical-board
acceptance.
