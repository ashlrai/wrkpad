# Support

## Start here

1. Run `npm run doctor` from the repository root.
2. Follow [setup and Flight Check](docs/setup.md).
3. Check [troubleshooting](docs/troubleshooting.md).
4. Search existing GitHub Issues and Discussions.

When asking for help, include macOS version and architecture, connection method, Work Louder Input version if known, source commit or packaged version, exact error text, redacted doctor output, and whether the problem occurs in development, a package, or both.

Do not post tokens, credentials, prompts, transcripts, private repository names, full local paths, or unredacted Flight Check receipts.

## Supported scope

The project currently supports:

- local macOS development and unsigned packaging;
- Creator Micro 2 shortcut routing through Work Louder Input;
- on-screen status from a compatible local `wrkpad` observer;
- read-only Fleet briefs from a compatible local Ashlr Hub CLI;
- app-level focus for Codex Desktop and cmux.

It does not currently support Windows or Linux, Creator Micro v1/QMK programming, physical RGB or firmware writes, exact task/pane focus, automatic provider installation, signed distribution, or remote Fleet control.

## Where to ask

- Use GitHub Discussions for setup questions and ideas.
- Use GitHub Issues for reproducible bugs and scoped feature requests.
- Use a pull request for an implementation with tests.
- Use GitHub private vulnerability reporting for security issues.

If private vulnerability reporting is unavailable, email [hello@ashlr.ai](mailto:hello@ashlr.ai). See [CONTRIBUTING.md](CONTRIBUTING.md#reporting-security-issues) for what to include.
